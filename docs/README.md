# OctoAcme Project Management Docs

Welcome! This folder contains living documentation of OctoAcme's project management practices. These docs provide actionable guidance for each project phase, roles, and collaboration norms. Start with the Project Management Overview for principles and key artifacts.

## OctoAcme Project Management Process Summary
OctoAcme delivers customer value through iterative, data-informed execution. Projects progress through clear phases: Initiation (validate problem, align stakeholders, create a one-pager), Planning (break work into shippable increments, identify dependencies and risks, create a release plan), Execution &amp; Tracking (day-to-day delivery with CI, PRs, testing, and regular syncs), Release &amp; Deployment (staged releases, smoke tests, rollback plans), and Retrospective &amp; Continuous Improvement (capture learnings and convert them to action items). Risk management and open communication are embedded throughout, and clear roles (PM, PdM, Developers, QA, Stakeholders) provide ownership and accountability.

## How to use these docs
- Keep the project one-pager and key artifacts updated in the project repo under docs/ or .copilot/ to let Copilot Spaces use them as context.
- Use the Project Initiation guide to create the project one-pager and confirm stakeholders.
- Follow the Planning and Execution docs for backlog, DoD, and PR/CI practices.
- Use the Risk &amp; Communication doc to maintain a risk register and escalate issues.
- Follow the Release guide for staging, smoke tests, and rollback plans.
- Run retrospectives regularly and convert action items into issues or backlog items with clear owners and due dates.
